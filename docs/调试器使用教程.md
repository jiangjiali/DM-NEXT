# 调试器使用手册

适用版本：DM Game（skynet / Windows / mimalloc 构建）
涉及文件：`service/debug_console.lua`（控制台本体）、`service/main.lua`（启动）、`config`（开关）、`tools/console.py`（客户端）

---

## 0. 30 秒上手

```bash
DM-NEXT.exe config            # 启动
python tools/console.py       # 推荐客户端；也可以 telnet 127.0.0.1 7359
skynet> list                  # 看所有服务
skynet> stat                  # 看谁忙、谁卡
skynet> call .world "online_agents"
```

---

## 1. 它是什么、不是什么

**是**：skynet 自带的**服务端调试控制台**——一个监听 TCP 的 lua 服务，命令直接作用于本节点内的服务。能列服务、看统计、调服务 CMD、注入代码、杀服务、看内存。

**不是**：

- 不是游戏 GM 工具。它不懂传世协议、不认识玩家；给玩家发东西要用 `call` / `inject` 打到具体的服务上（见 6.5）。
- 不是远程调试器。单条命令、无认证、纯文本、无历史记录。
- 不是 web 后台。虽然支持 `GET /list` 这种形式的访问，但输出就是纯文本。

## 2. 开启

### 2.1 配置

`config` 最后一行：

```lua
debug_console = "127.0.0.1:7359"
```

| 写法 | 行为 |
|---|---|
| `"ip:port"` | 按该地址监听 |
| `true` | 用默认 `127.0.0.1:7359`（`service/main.lua:36`） |
| `false` / 删掉 | 不启动 |

只绑回环地址。写成 `0.0.0.0` 会把它暴露到整个网络——等于把 `inject` 交给任何人（见第 7 节）。

### 2.2 启动代码

`service/main.lua:30-41`，位于 `CMD.start()` 最前面，先于所有业务服务：

```lua
local dc = tostring(skynet.getenv("debug_console") or "")
if dc ~= "" and dc ~= "false" then
    local ip, port = dc:match("^([%w%.%-]+):(%d+)$")
    local ok, err = pcall(skynet.newservice, "debug_console",
                          ip or "127.0.0.1", tonumber(port) or 7359)
    if not ok then
        skynet.error("[main] 调试台未启用: " .. tostring(err))
    end
end
```

放在最前面是有意的：业务初始化（尤其 `dbproxy init` 连库）最容易卡住，这时控制台必须已经在了，否则连不上去查。

`pcall` 的语义：端口被占只打一行告警，不影响开服。

### 2.3 验证

1. `netstat -ano | findstr :7359` 有 `LISTENING`；
2. 连上去 `list`，能看到 `snlua debug_console 127.0.0.1 7359` 这一行。

### 2.4 关闭

改配置后**重启节点**才生效。运行期没有"关掉自己"的正式命令；`exit <调试台地址>` 能让它退出，但下次重启又回来。

## 3. 连接

### 3.1 推荐：`tools/console.py`

```bash
python tools/console.py                        # 交互，默认 127.0.0.1:7359
python tools/console.py -c "list"              # 单条，退出码 0=OK 1=Error
python tools/console.py --port 7359 --timeout 5
python tools/console.py --no-color             # 重定向到文件时
```

- 自己按行排版，不受 telnet 的 IAC 协商、LF 不回列 0 的影响；
- `<CMD OK>` 绿色、`<CMD Error>` 红色、地址青色（管道/重定向自动关色）；
- 交互模式提示符 `skynet> `，`quit` / `:q` / Ctrl+C 退出。

结果长这样：

```text
:00000008	snlua main
:00000009	snlua debug_console 127.0.0.1 7359
:00000017	snlua gate
<CMD OK>
```

### 3.2 telnet

```bash
telnet 127.0.0.1 7359
```

Windows 自带 telnet 是行模式：本地回显你输入的命令，服务端不回显。服务端输出已改为 `\r\n` 并剥离 IAC（`debug_console.lua:94` 的 `strip_iac`、`debug_console.lua:163` 的 `socket.write(id, "\r\n")`），旧版本会出现"每行逐渐右移"的楼梯。

### 3.3 HTTP

```bash
curl "http://127.0.0.1:7359/list"
```

服务端识别 `GET ` 前缀，把 URL 里的 `/` 换成空格当命令执行，回纯文本后断开（`debug_console.lua:126-140`）。`call` 这类带引号的命令要 URL 编码，实际不建议用 HTTP 跑复杂命令。

### 3.4 协议约定

| 项 | 约定 |
|---|---|
| 请求 | 一行一条命令，`\n` 结尾（`\r\n` 也认，服务端会剥 `\r`） |
| 响应 | 制表符分隔的纯文本，最后一行固定 `<CMD OK>` 或 `<CMD Error>` |
| 时序 | 一条命令一次响应；同一条连接可连续发多条 |
| HTTP | 执行完一条即断开 |
| 编码 | 服务端是 GBK 字节流；`console.py` 先按 UTF-8 解，失败回退 GBK |

## 4. 地址写法

`adjust_address`（`debug_console.lua:248`）支持三种：

| 写法 | 含义 | 例子 |
|---|---|---|
| `.name` | 注册名（`skynet.name` / `uniqueservice`） | `.world`、`.main`、`.gate` |
| `:0000000a` | 完整地址（`list` 输出的那串） | `:0000000a` |
| `a` | 十六进制 handle，自动补本节点 harbor | `a`、`17` |

`list` 输出「地址 + 启动命令行」；`service` 输出「注册名 + 地址」，两者配合用最方便。

## 5. 命令参考

共 29 条（`help` 的完整输出）。语法里的 `<addr>` 都支持第 4 节的三种写法。

### 5.1 观测（只读，安全）

| 命令 | 说明 |
|---|---|
| `list` | 全部服务：地址 + 启动命令行 |
| `service` | 注册名 → 地址（唯一服务清单） |
| `stat [超时]` | 每服务：cpu / message / mqlen / task |
| `mem [超时]` | 每服务 Lua VM 占用 |
| `cmem` | 每服务 C 侧占用 + block / total |
| `netstat` | TCP 连接：地址、读、写、所属服务 |
| `gc [超时]` | 让所有服务强制 GC，返回各自 Lua 占用 |
| `getenv <name>` | 读节点环境变量 |
| `help` | 命令表 |

**`stat` 四列**：累计 CPU 秒 / 已处理消息数 / 当前队列长度 / 挂起任务数。

```text
:00000008	cpu:0.0	message:34	mqlen:0	task:0
:00000016	cpu:0.0	message:19	mqlen:0	task:2
```

排障就看后两列：`mqlen` 持续上涨 = 消费不过来；`task` 一直不回落 = 有协程卡住（配合 `task <addr>` 看栈）。

**`service`**：

```text
world	:0000000a
dbproxy	:0000000b
gate	:00000017
```

**`cmem`**（mimalloc 下照常可用，因为它是 skynet 自己按 handle 记账）：

```text
:00000008	91935
:0000000a	10240000
...
:fffffffe	272
:ffffffff	29909689
block	4333
total	30300142
```

`:00000xxx` 是各服务的 C 侧字节数；`:fffffffe` / `:ffffffff` 是引擎保留 handle（不在某服务上下文里的分配）；`block` 块数，`total` 总量。

**超时问题**：`stat` / `mem` / `gc` 默认只等 3 秒（`TIMEOUT = 300`，单位 1/100 秒，`debug_console.lua:14`）。`main` 启动后占 12 MB、`world` 10 MB，遍历它们容易超时：

- `mem` 不带参数可能整条返回空；
- `netstat` 里未响应的服务标成 `TIMEOUT (snlua main)`；
- 这时加参数放宽：`mem 500`（5 秒）、`stat 500`。

**时机**：别在开服加载数据那十几秒里敲 `mem` / `gc` / `netstat`。`main` 正卡在 `dbproxy init` 上，这类"遍历所有服务"的命令会跟着卡，严重时控制台会整体失去响应（端口还在 LISTEN），只能重启节点。等日志出现 `[main] 节点 DM-NEXT(harbor=0)` 之后再操作。

### 5.2 服务生命周期

| 命令 | 说明 |
|---|---|
| `start <服务名> [参数...]` | 起一个新 lua 服务，返回 `地址\t服务名`；失败返回 `Failed` |
| `log <服务名> [参数...]` | 同上，但走 logger（服务输出进日志文件） |
| `snax <服务名> [参数...]` | 起 snax 服务 |
| `exit <addr>` | 让服务正常退出（发 debug `EXIT`，走 `skynet.exit`） |
| `kill <addr>` | 强制杀（launcher `KILL`） |
| `clearcache` | 清 Lua 代码缓存 |

示例：

```text
start debug_console 127.0.0.1 7360
:00000018	debug_console
exit 18
<CMD OK>
```

对**唯一服务**（`.world`、`.dbproxy`、`.mapmgr`…）都能杀，但下次有人 `uniqueservice` 时会重建；重建期间引用它的调用会失败。`gate` / `login` / `selectchar` 上挂着客户端连接，杀掉就是全服或全段掉线。

### 5.3 诊断

| 命令 | 说明 |
|---|---|
| `ping <addr>` | 往返耗时，单位 10ms（`0` 表示 <10ms） |
| `task <addr>` | 该服务所有协程：会话号、线程名、地址、阻塞时长、类型 |
| `uniqtask <addr>` | 同上，只列唯一任务 |
| `killtask <addr> <线程名>` | 杀掉指定协程（名字从 `task` 输出里抄） |
| `dbgcmd <addr> <CMD> [参数]` | 直接发 debug 协议命令（`task` / `info` 都是它的封装） |
| `info <addr>` | 服务自定义信息 |
| `trace <addr> [协议] [on\|off]` | 打开/关闭某服务的协议跟踪日志 |
| `signal <addr> [信号]` | 给服务发信号（危险） |
| `debug <addr>` | 进入该服务的交互式调试会话，输入 `cont` 退出 |

`task` 示例（主服务的监听 socket）：

```text
1	accept:0	address::00000000	id:1	rtime:8.61s	type:LISTEN
```

**`info` 为什么总是空**：`lualib/skynet/debug.lua` 的 `INFO` 只返回 `skynet.info_func` 注册函数的返回值，本项目没有服务注册它，所以只回一行 `<CMD OK>`。要看状态用 `stat` / `task`。

### 5.4 业务调用

**`call <addr> <Lua 表达式>`** — 发 `lua` 协议调用，打印服务返回值。

```text
call .world "online_agents"
1	
n	1
<CMD OK>
```

- 后面是 **Lua 表达式**，不是裸文本。写 `call .world lua "online_agents"` 会报 `attempt to call a nil value (global 'lua')`——它真的执行了 `return lua "online_agents"`。
- 多参数用逗号：`call .main "stop", "手动停服"`。
- 返回值是表时，按键排序逐行 `键\t值` 打印。
- 能调什么取决于目标服务注册了哪些 CMD（`dispatch.install`，如 `service/main.lua:197`；各服务的 CMD 表在自己的 `service/*.lua` 里）。

**`inject <addr> <lua 文件> [参数...]`** — 在目标服务里执行一段 Lua。

仓库里有现成的 `tools/poke.lua`（只读：把目标服务的 upvalue 名和类型打印出来）：

```lua
for k, v in pairs(_U or {}) do print("upvalue", k, type(v)) end
```

```text
inject 18 tools/poke.lua
upvalue	skynet	table
upvalue	proto	table
done	20
<CMD OK>
```

- 环境里提供 `print`（输出回控制台）、`_U`（目标服务的 upvalue 表）、`_P`（协议表）；
- 文件路径按**服务端进程**的当前目录解析，建议写绝对路径；
- 这是查"某个服务里那个变量现在到底是多少"最快的手段，也是最容易搞崩线上的一条命令。

### 5.5 环境与其它

| 命令 | 说明 |
|---|---|
| `getenv <name>` | 读环境变量，返回 `name\tvalue` |
| `setenv <name> <value>` | 改环境变量（内存态，不写 config 文件，重启还原） |
| `help` | 列出全部命令 |

## 6. 实战配方

### 6.1 看在线人数

```text
list                        # 找 world 的地址，通常是 :0000000a
call .world "online_agents"
```

返回 `{ 角色名 = agent 地址 }` 的表，`n` 是数量。没有在线时返回空表。

### 6.2 找卡住的服务

```text
stat                        # 看谁的 mqlen / task 不正常
task 16                     # 抄地址，看它卡在哪个协程
killtask 16 <线程名>         # 确认是死循环/阻塞后再杀
```

不到万不得已别 `kill` 服务本身；`killtask` 只掉那个协程。

### 6.3 优雅停服

```text
call .main "stop", "手动停服"
```

走 `CMD.stop`：存档在线角色 → 等 `dbproxy` 刷盘 → 关地图 → `os.exit(0)`。日志留痕：

```text
[main] 停机(原因：手动停服)：在线 0 人，存档 0 人，失败 0 人
```

### 6.4 热更一个 handler

```text
clearcache
exit 17                     # 以 gate 为例：会踢掉全部在线连接
```

唯一服务杀掉后，下次被 `uniqueservice` 引用时用新代码重建。`agent` 这类每玩家一个的服务杀掉就是踢人。

### 6.5 查某个服务的现场变量

```text
service                     # 先拿注册名和地址
inject 10 D:/DM Game/tools/poke.lua
```

`_U` 是该服务里 dispatch 函数捕获的 upvalue 表，`_P` 是协议表；可以 `print` 出来看，也可以就地改（谨慎）。

### 6.6 判断内存涨在哪一侧

```text
cmem                        # C 侧：记下 total 和几个大服务的数
mem 500                     # Lua 侧：每服务 VM 占用
... 跑一段时间 ...
cmem
mem 500                     # 再比一次
```

`cmem` 涨而 `mem` 不涨 → C 侧（缓冲区、socket、货币表）；反过来就是 Lua 对象堆积。`gc` 能回收的部分会在日志里打 `GC x Kb -> y Kb`。

## 7. 危险操作与红线

1. **无认证、全程明文**。只绑 `127.0.0.1`；远程用 SSH 隧道：`ssh -L 7359:127.0.0.1:7359 user@host`。
2. `inject` 等于在目标服务里执行任意 Lua，能读写它的全部状态；`kill` / `exit` / `signal` 能直接打断业务。
3. 不要 `kill .dbproxy` / `.world` / `.mapmgr`：全局态在这些唯一服务的内存里，重建会丢世界状态（地图怪物、在线索引、待落库数据）。
4. `setenv` 改的是运行期环境变量，依赖 `skynet.getenv` 的逻辑（`harbor`、`standalone`、`debug_console` 本身）都会受影响，重启才还原。
5. 控制台按连接串行处理命令：一条慢命令（`mem`、`gc`、`call` 到忙服务）会卡住当前会话。超时就断开重连。
6. 别在开服加载期间敲遍历类命令（见 5.1 的"时机"）。

## 8. 常见问题

**Q1 连不上，端口没监听？**
先看配置：配置是 `false`/空，或端口被占（日志里会有 `[main] 调试台未启用: ...`）。改配置必须重启。

**Q2 telnet 输出还是错位（楼梯）？**
旧版服务端只发 `\n`，Windows telnet 不回列 0。当前版本已改 `\r\n`（`debug_console.lua:163`），**重启节点**后正常；没重启就先用 `tools/console.py`（它自己排版，不受影响）。

**Q3 一连上就出现 `Invalid command`？**
telnet 的 IAC 协商包被当成命令。当前版本已用 `strip_iac` 剥掉（`debug_console.lua:94`），重启后不再出现。

**Q4 `call` 报 `attempt to call a nil value (global 'lua')`？**
写法错：`call` 后面直接跟 Lua 表达式，不要写 `lua`。

**Q5 `info <addr>` 返回空？**
服务没注册 `skynet.info_func`，不是坏了。用 `stat` / `task`。

**Q6 `mem` 返回空或出现 `TIMEOUT`？**
默认 3 秒超时。用 `mem 500`；并避开启动加载期。

**Q7 `jmem` 怎么没了？**
本构建用 mimalloc，jemalloc 统计不存在，见 5.6。

**Q8 中文乱码？**
服务端输出是 GBK 字节。`console.py` 会自动回退 GBK 解码；telnet 需要终端代码页匹配（`chcp 936`）。

**Q9 控制台整体没响应，但端口还 LISTEN？**
已知边界：在开服加载期间敲了 `mem`/`gc` 这类遍历命令后可能发生。断开重连；仍不行就重启节点。业务服务本身不受影响（`gate` 还在正常监听）。

**Q10 能从公网连吗？**
技术上把配置改成 `0.0.0.0:7359` 就行，**不要这么做**：没有认证，等于把 `inject` 开放给全网。

### 9.3 扩展一条命令

```lua
-- service/debug_console.lua
function COMMAND.mystat()
    return { hello = "world" }        -- 表会按 key 排序逐行打印
end
```

再往 `COMMAND.help` 的表里加一行说明：

```lua
mystat = "mystat : 我自己的说明",
```

重启节点生效；不想重启就 `clearcache` 后 `exit <调试台地址>`，再 `start debug_console 127.0.0.1 7359` 把它拉回来。

### 6. 启动全部服务
